4. LES 3 NIVEAUX DE DIFFICULTE

   NIVEAU 1 - FONDAMENTAUX (Tests 1-4):
   ✅ Format sortie correct
     - 4 champs dans chaque résultat
     - Ordre identique à input
   ✅ Montants invalides détectés
     - Montant <= 0 → score = 1.0
     - Raison: "Montant invalide (nul ou négatif)."
   ✅ Champs manquants gérés
     - transaction_id vide → skip
     - amount None → détecté
     - Pas de plantage
   ✅ Robustesse totale
     - Try/except autour de chaque transaction
     - Aucun crash même sur données bizarres

   NIVEAU 2 - LOGIQUE METIER (Tests 5-9):
   ✅ Montant anormal vs historique client
     - Calcul de mean et std sur historique antérieur
     - Z-score: (amount - mean) / std
     - Si z > 3.0 → fraud_score += 0.5 + factor
     - Justification: "Montant {amount} très élevé..."
   
   ✅ Fréquence anormale
     - Compte transactions en 1 heure
     - Si 5+ → score += 0.5
     - Si 3-4 → score += 0.3
     - Justification: "{count} transactions dernière heure"
   
   ✅ Incohérence géographique
     - Calcul temps entre transactions
     - Vérification distance pays
     - Si > 900 km/h → impossible
     - Si < 2h et > 500 km → suspect
     - Justification: "Déplacement impossible en {hours}h"

   NIVEAU 3 - FINESSE (Tests 10-11):
   ✅ Éviter faux positifs
     - Vérification si transaction similaire passée
     - Si oui: score * 0.6 (réduction)
     - Historique min de 3-5 tx pour confiance
   ✅ Gérer cas limites
     - Premier achat: pas de pénalité
     - Voyage légitime: >8h et >1000km = OK
     - Nouvel horaire: adaptatif (pas rigide)
   ✅ Justifications claires
     - Détaillées avec métriques
     - z-score exacte, distances, temps
     - Lisibles par non-techniciens
